# SAA-C03 Lab 06: Application Load Balancer – Sticky Sessions

## 🎯 Tasks
1. Enable **stickiness** on an ALB target group.
2. Configure a **load balancer-generated cookie**.
3. Verify that repeated requests from the same browser reach the same EC2 instance.
4. Inspect cookies using browser developer tools.
5. Disable stickiness and verify normal load balancing.

---

## 🧩 Step 1: Open the Target Group

1. Go to **AWS Console → EC2 → Target Groups**.
2. Select `saa-alb-tg-01` from Lab 03.
3. Choose **Actions → Edit target group attributes**.
4. Locate the **Stickiness** setting.

---

## 🔹 Step 2: Enable Sticky Sessions

1. Enable **Stickiness**.
2. Select the stickiness type:

- **Type:** Load balancer generated cookie
- **Duration:** 1 day (default for this exercise)

3. Save the changes.

👉 The ALB uses a cookie to direct subsequent requests from the same client to the same target while stickiness remains valid.

---

## 🔹 Step 3: Verify Sticky Sessions

1. Open the ALB DNS name in your browser:

```text
http://<ALB-DNS-NAME>/
```

2. Refresh the page several times.
3. Observe the response from the EC2 instance.

👉 Repeated requests from the same browser should normally reach the same target while the cookie remains valid and the target is healthy.

---

## 🔹 Step 4: Inspect Cookies

1. Open browser **Developer Tools** using `F12`.
2. Select the **Network** tab.
3. Refresh the ALB page.
4. Select a request and inspect **Cookies** or the request/response headers.

For ALB load-balancer-generated stickiness, look for the `AWSALB` cookie.

👉 The browser sends the cookie on subsequent requests, allowing the ALB to maintain session affinity.

---

## 🔹 Step 5: Explore Application-Based Cookies

1. Return to **Target Groups → `saa-alb-tg-01` → Edit attributes**.
2. Inspect the application-based cookie option.
3. Review the application cookie name setting.
4. Do not enable it unless your application is configured to issue the corresponding cookie.

The lecture covers two categories:

- **Application-based cookies:** Generated by the application or target, or using an ALB-generated application cookie.
- **Duration-based cookies:** Generated by the load balancer with a configured duration.

The application-based cookie name must not use reserved names such as `AWSALB`, `AWSALBAPP`, or `AWSALBTG`.

---

## 🔹 Step 6: Disable Stickiness

1. Return to **Target Groups → `saa-alb-tg-01` → Edit attributes**.
2. Disable **Stickiness**.
3. Save the changes.
4. Refresh the ALB endpoint and observe requests again.

👉 Without stickiness, requests can be distributed among healthy targets according to the ALB's routing behavior.

---

## 🧹 Step 7: Cleanup

1. Disable stickiness if you want to restore the target group's original configuration.
2. If continuing your ALB labs, keep the shared resources.
3. If finishing the entire ALB practical, delete the ALB and target group, terminate the EC2 instances, and remove unused security groups.
